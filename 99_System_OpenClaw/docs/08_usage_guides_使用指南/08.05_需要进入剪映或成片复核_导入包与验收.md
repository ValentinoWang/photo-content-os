# 08.05 需要进入剪辑或成片复核：剪辑交接与验收

适用场景：项目已有脚本、Storyboard 和 EDL，需要开始人工精剪；或已有
候选成片，需要做技术质检和人工 Final 判断。

## 先选剪辑交接方式

项目总览中记录的剪辑方式决定本版本的交接物。默认是**标准剪辑交接**；
只有人在项目仍适合切换时明确选择，才使用**自动生成可编辑时间线**。

| 你要做什么 | 选择 | 得到什么 |
| --- | --- | --- |
| 我自己在常用软件中剪 | 标准剪辑交接 | 清单、片段顺序、字幕和交接说明 |
| 我需要一条可继续修改的时间线 | 自动生成可编辑时间线 | OTIO、Kdenlive 工程和校验记录 |

同一项目版本只能选择一种。时间线环境缺失、素材无法重连或校验失败时，系统
写“已阻塞”；不会偷偷改走另一种方式。

## 标准剪辑交接（默认）

云端创建 `generate_edit_handoff_pack` 任务，Mac 输出：

```text
90_Draft_Project/edit_handoff/{项目版本}/
├── manifest.json
├── clips.csv
├── captions.srt
├── 剪辑交接说明.md
└── 预览说明.md
```

人打开交接说明，按片段顺序和字幕开始精剪。可以使用剪映，也可以使用其他合适
的软件；系统不要求向任何软件导入专有草稿。

## 自动生成可编辑时间线（可选）

云端创建 `generate_otio_kdenlive_timeline` 任务，Mac 输出：

```text
90_Draft_Project/edit_handoff/{项目版本}/
├── timeline.otio
├── timeline.kdenlive
├── timeline_validation.json
└── 剪辑交接说明.md
```

这条路线只使用固定的本机运行环境生成和验证时间线。Kdenlive 或所需运行环境
不可用时，任务会停止并说明需要处理什么；不会替换为标准剪辑交接或别的编辑器。

## 人工精剪与导出

人负责镜头取舍、音乐、节奏、字幕、封面、调色和特效。若使用剪映，真实草稿留在：

```text
03_Jianying_Active_Drafts/
```

它不进入同步盘，不由自动化移动或写入。导出物回到项目：

```text
91_Output/V1/
91_Output/V2/
91_Output/Final/
```

## 成片复核与发布

`local_output_review` 只生成质检证据和返修建议。它不自动宣布最终版，不发布，也
不改变项目阶段。人确认当前版本为 Final 后，项目才可以进入“可发布”；人完成平台
发布并回填链接后，项目才成为“已发布”。

## 剪到一半想改

不要直接覆盖剪辑文件。向 Media Bot 说“修改这个项目”，说明想改哪里、想改成什么、
原因、是否着急和可选参考。Bot 会先复述并让你选：**先记下**、**只改一小处**或
**现在修改**。只有你看过影响并确认执行后，系统才创建新版本的修改工作；旧版本仍
可用于对比。

## 历史导入包说明

旧项目可能仍有 `native_import_packs`、`06b_jianying_draft_plan.json`、
`06d_native_import_pack_result.yaml` 或真实剪映草稿。这些文件是历史交付证据，不能
删除，也不能作为当前 v0.2 项目的新生产路线。

## 不要做

- 不把历史导入包当作已完成粗剪或当前项目证据。
- 不让自动化直接写真实剪映草稿。
- 不因时间线环境失败而自动换剪辑方式。
- 不让本地质检代替人工 Final 判断或平台发布。
