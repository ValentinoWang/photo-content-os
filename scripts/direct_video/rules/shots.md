# 镜头代码规则

来源：用户技能 `direct-video-shots`；动作、禁用和观感规则部分借自 HeyGen HyperFrames（Apache-2.0）。

## 渲染器硬规则（违反就渲染失败）
- 画布 1080×1920，`html,body{margin:0;width:1080px;height:1920px;overflow:hidden}`。
- `window.seekFrame = (frame, fps) => {…}`：`t = frame / fps`，确定地画到那一刻，同一帧永远同一张图。文件顶部写 `const D = <秒>`。
- 每镜第 0 帧就有不透明的页眉和主图雏形，不能把所有元素一起从零透明度淡入，不能出现全空的暗色帧。
- 出现时机：**D 还是估算值时**，所有元素在 0.7·D 之前出完（给配音偏快留余量）；**D 已是配音实测时长时**，元素跟着句级时序出现（`sentence-timings.json` 里这句开始的时刻），最后一个元素不晚于 D − 0.4 秒，之后停在完整画面上。
- 禁用 `setTimeout` / `setInterval` / `requestAnimationFrame` / `Math.random`（要随机就写固定种子）；不读任何外部资源（CDN、网络字体、图片、`fetch`、`url(`、`@import`），图形用内联 SVG / CSS；没有 `<video>` `<audio>`。单文件 < 100,000 字符（`renderCode` 上限）。
- 字体被强制成华文黑体 Medium 一种字重：层次只靠字号、颜色、留白。中文标点用全角；问号、感叹号用 `<span class="fw">？</span>`，并设置 `.fw{display:inline-block;width:1em;text-align:center}`，避免锁定字体把标点挤在左半边。
- 页眉（眉题、标题、副标题、页码、进度条）包在 `data-role="header"` 的元素里：检查脚本靠它把页眉和主画面分开，没有就报 ERROR。
- **底部 y ≥ 1536 不放文字和关键图形**：保留底部安全留白；本直出流程不烧录字幕，不声明成片带有字幕。两侧 ≥ 72px；正文 ≥ 44px，标签 ≥ 34px；正文对比度 ≥ 4.5:1。

## 每一镜怎么动
- **一镜一个主动作**：次要动作的幅度是主动作的 50–70%，晚 100–200 毫秒开始，其余元素不动。主体至少占画面高度或宽度的 40%。
- **图解逐步长出来**：口播说到哪一部分，那一部分才出现；不把画完的整张图一次放上去。先想清楚这句话是什么形态（数字落地、推翻误解、前后对比、按步骤、多中选一……），再画；相邻两句是同一形态时换一种画法。
- **图要讲出东西**：图解揭示机制，图表证明一个论点，动起来的东西表示变化。画之前把每一步的道理核一遍：画得好看但讲错了，比不画更糟。
- **画面上的字不重复口播原句**：页眉和主画面上的字是要点或标注，不把这一镜口播的整句再写一遍（本流程没有烧录字幕）。字太多就删字，不缩字号。
- **数字**：数字是画面上最大的东西；跳动 1.2–1.6 秒后停住，同一屏只让一个数字跳；来源一行小字写在画面上。锁定字体的数字本来等宽（实测 1111 与 8888 同宽），跳动不会抖。
- **图表**：按「框和轴 → 参考线 → 数据画入 → 一条注释落在关键点」出现；不放图例；只突出一组数据，其余置灰；不做饼图和仪表盘。
- **末镜停在 `takeaway` 上**：末镜画面在最后一句开始时就已经完整，之后不再出新元素，到 D 至少停 `endHoldSeconds` 秒。停不够是上游最后一句太短，报给上游改口播；不拉长动画，也不补静音。

## 默认禁用
没有参考形式时（有 `form_profile.visual_grammar` 就照它，见「观感」），下面这些是 AI 生成片的露馅套路，默认不用：

- 暗色虚空里漂着小元素；光晕、泛光、霓虹、粒子。
- 紫蓝渐变、网格渐变、毛玻璃卡片。
- 米色或米白纸底配衬线大标题、斜体强调词、「01 / 02」编号、等宽小写标签、胶囊形标签。
- 每个元素都居中对齐（主画面在内容区居中摆放不算）、全部同时淡入、全部从下往上滑入；字在被读的时候还在动。
- 装饰性的角标、边框、HUD；三张卡片并排、KPI 网格、圆圈里放图标、一屏要点列表；压暗截图上叠标题。

## 观感
- 全片同一套视觉系统：同一底色、一个主色、一个强调色加中性色，固定页眉和字号层级，颜色带固定语义，每镜都一样。
- **模仿爆款时，视觉系统从拆解的形式说明（`form_profile.visual_grammar`）来**：底色明暗、强调色的数量和角色（例如「唯一的暖色只标结论」）、标题/解释字层级、一屏信息密度、图解手法（模型、累积模拟、对照、公式揭晓）都照形式说明做。要避开的只是「可辨认的原样组合」（同样的图形 + 构图 + 元素放在一起），靠**换图形和构图**避开，不靠换掉整个色彩体系（R131 第二版把深底换成米色纸面，形式就丢了）。没有参考形式时，才自己定一套。
- **强调色只有一个**：形式说明写「唯一强调色」时，全片只用这一个颜色标结论/答案；关键词的强调用更亮的中性色或字号，不再引入第二个彩色。
- **竖屏构图要撑满内容区**：主画面落在页眉以下、字幕带以上的内容区（约 y 200–1500）的中部，成片末帧内容下沿到字幕带之间的空带不超过内容区高度的 30%。参考作品是横屏时尤其要注意：横屏的「留白」搬到竖屏会变成下半屏一大块死黑。卡片、圆点阵、图表按竖屏放大，不要照横屏比例缩在上面。
- 每一拍一个主画面，是数据或机制的图解，不是一屏字。一镜超过 6 秒就分拍，每拍 4–6 秒，跟着口播的句子换；一拍里超过 3 秒画面完全不动会报 WARN（故意的停顿在 `<body data-hold="起-止">` 里标出来）。
- 研究出处可以一行小字标在画面上（作者 等，年份），不放 DOI；示意图要标「示意图，非原始数据」。
