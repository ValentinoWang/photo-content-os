# photo-content-os 用自己的开发机跑测试、门禁和渲染

状态：待确认

## 我的理解

1. 新租的这台开发机专给 photo-content-os 用。装好和本机一样的 Python、Node、剪辑工具、浏览器和 ffmpeg，以后测试、门禁、拍图和渲染都在开发机上跑，本机不再跑这些重活。
2. 仓库里放一个 rbox 脚本：一条命令把改动推到开发机，再在开发机上跑命令；全量测试和门禁要排队，同一时间只跑一个。
3. 照片、视频、证据截图和密钥不随代码推到开发机；开发机上不装 Claude、Codex，也不放 AI 凭据。
4. R277、R278 门禁要复制本机真实的 Studio 数据（有照片）。用户同意后，只推这两个门禁用到的那几份（约 1.8 GB）；作品连着的真实照片项目不推，只在开发机上建空目录占位。R278 门禁搬到开发机跑；R277 门禁的标注框位置按 Mac 的中文字体量，开发机上量不出同样的数，所以还在本机跑（我补充的）。

## 不做的

- 不把作品连着的真实照片、视频项目（素材根里约 8.7 GB）放到开发机
- 不改产品代码和门禁脚本（门禁里写死的 macOS 命令和字体路径，用开发机上的替身对付）
- 不和 Cadenvo、寸木、茶思屋的开发机共用

## 验收标准

### H-01

怎么操作：
1. 打开本机的活动监视器，按 CPU 排序。
2. 发送给 Claude：「跑一遍浅色界面的测试」。
3. 查看 Claude 回复的测试结果和活动监视器。

应该看到：测试结果显示通过；跑测试的这段时间，活动监视器里本机没有新出现的测试进程或无头浏览器。

### H-02

怎么操作：
1. 发送给 Claude：「列出这次会推到开发机的文件清单」。
2. 检查清单里的照片、视频、截图和密钥文件。

应该看到：清单里没有个人照片、视频、截图和密钥；能看到的图片和视频只有风格库样张和合成的测试画面，它们本来就在仓库里。
