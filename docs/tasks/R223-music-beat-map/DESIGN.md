- 2026-10-20 的讨论（`docs/discussions/2026-10-20-music-tagging/`）结论：音乐库现在没有任何选曲标签，BPM、节拍、段落三个字段全是空的。

- 没查 Dribbble：这是在现有音乐页上加组件，项目已有设计系统，按全局规则不查。节拍图借 DJ 软件常见的两层结构：上面一条看整首，下面一条放大看拍子。筛选借电商的分面筛选。只借结构，画面沿用 `studio/static` 的令牌和组件。

## 3. 改了什么（从什么改成什么）

1. **右侧栏顶部（节拍图）**：
   - 原来：一条波形 + 播放按钮。
   - 现在从上到下：
     - 整首波形，已播部分照旧亮色；
     - 段落色带，三种深浅，段落名见清单 `sections.kinds`；
     - 图例；
     - 播放按钮、时间、当前第几小节和段落；
     - 放大区：播放位置前后共 8 秒，每拍一根短柱，柱高是这一拍的响度；每小节开头有竖线和小节号，那一拍的柱子更宽；
     - 播放线：中段固定在中间，开头和结尾自己移动。
2. **右侧栏「AI 标注」区（新增）**：
   - 放在歌手名下面，标题、行的顺序、各类名字都取自清单 `display`。
   - 每类一行，列出过了阈值的标签。风格那一行在大类后面带细分风格原名，例如「电子 Tropical House」。
   - 某类一个都没有时，显示清单里这一类的 `empty_text`；人声拿不准时显示 `uncertain_text`。
3. **右侧栏「节拍」一行**：原来写「还没分析 / 第一次用来配乐时自动分析」，改名「速度」，显示「117 BPM / 每小节 4 拍」；没分析好时不显示这一行，状态在顶部说。
4. **列表**：
   - 时长后面加「速度」一列，可能显示「117 BPM」「排队中」「分析中」或「没分析出来」（警示色）。
   - 宽 ≤1180 时仍然隐藏导入时间。
   - 每首歌名下面多一行圆角标签，按清单 `display.row` 组合，例如「电子 夏日 有人声」。
   - 标签没标出来时，这一行写「标签没标出来」（警示色）。
   - 手机上「速度」并进歌名下面那行：「网易云音乐 · 117 BPM」。
5. **筛选（分面筛选）**：来源那一行下面加一行标签筛选。
   - 分组顺序取自清单 `display.filter_order`，每组前面有小字组名。
   - 同一组里可以多选，满足任意一个就算；不同组之间要同时满足；还可以和来源筛选叠加。
   - 只列出在当前条件下还剩得下歌的标签，后面的数字是选上它会剩几首；已选中的标签一直显示。
   - 一行放不下时横向滑动，不折行。
6. **授权信息全部删除**（用户 2026-10-21 定，已存数据一起删）：
   - 列表去掉「授权」列和「平台版权曲 / 来源不明」小标签；
   - 右侧栏去掉授权小标签和「只用来定切点和在本机预览…」那段说明。
   - 数据层同时删掉 `license_status`、`attribution` 两个字段：规范、入库代码、命令行输出、测试、当前文档里都删；库里已存的曲目先备份再迁移。范围见 `TASK.md`。
7. **筛选后没有歌**：列表里写「这样筛选没有歌。」，旁边一个「清除标签筛选」按钮；右侧栏收起。
8. 页面其余部分（导入框、空库、导入中、重复、会员、抖音各状态）不变，只是右侧栏和列表跟着去掉授权。

## 4. 状态

| 设计状态 | 什么时候 | 页面上显示 |
|---|---|---|
| `music` | 选中的歌节拍、标签都好了。播放中、停着、前奏没拍子、快到结尾、筛选中都属于这个状态 | 节拍图、AI 标注区、速度行 |
| `music-beats-queued` | **最差首屏**：功能上线后库里 3 首都要补分析，默认选中的 Turn Back Time 在排队 | 波形（不分色）、「排队等分析，前面还有 N 首。」；没有 AI 标注区、没有标签筛选行；列表速度列显示「分析中」或「排队中」 |
| `music-beats-analyzing` | 选中的歌正在分析（例如刚导入） | 「正在分析节拍和标签」和来回走的细进度条 |
| `music-beats-failed` | 节拍分析中途出错，可重试 | 警示块：「节拍没分析出来」+「分析到一半出错了，可以再试一次。」+「重新分析」。标签照常显示（部分失败） |
| `music-beats-failed-unreadable` | 音频文件读不出来 | 警示块，正文让用户换文件重新导入，**不给**「重新分析」 |
| `music-beats-failed-unknown` | 失败原因没认出来 | 警示块：「没认出是什么原因，可以再试一次。」，后面用等宽字显示失败代号，给「重新分析」 |
| `music-tags-failed` | 节拍好了，标签没标出来（部分失败） | AI 标注区换成警示块：「标签没标出来」+「分析到一半出错了，可以再试一次。」+「重新标注」；列表这首的标签行写「标签没标出来」 |
| `music-filter-empty` | 来源和标签叠加后一首都没有 | 「这样筛选没有歌。」+「清除标签筛选」，右侧栏收起 |

- 前奏没拍子（CRUSH VIBE 前 8 秒测不到拍子）时，放大区中间写「这一段没有测到拍子」；还没到第一小节时不显示小节号，只显示段落。
- 页面级状态按**选中那首歌**的分析状态定，`mark()` 用上表的名字；筛选后没有歌时用 `music-filter-empty`。

## 5. 交互

- 点整首波形或色带：跳到那个位置，放大区跟着跳。
- 播放时：放大区随播放滚动；播放线经过的那一拍变成白色。这是 H-02「拍子对不对得上」靠眼睛和耳朵核对的依据。
- 点「重新分析」「重新标注」：**立刻**把这首改成「分析中」，列表和右侧栏一起改，不等服务器回应（见 Core `ai-coding-error-lessons.md` 轻操作一条）。「重新标注」只重跑标签，不重跑节拍。
- 分析状态变化不刷新页面也要更新：「排队中 → 分析中 → 数字和标签」。实现方式（轮询或推送）由后端定，轮询间隔不长于现有导入轮询的 1 秒档。
- 点标签筛选：列表即时过滤。选中的歌被筛掉时，右侧栏换成筛选后的第一首。
- 鼠标停在色带某一段上：提示「高潮 1:25–1:43」这样的段名和起止时间。
- AI 标注区这次只读。以后开放人工审核时就在这一区里改，规则见清单 `governance`、`storage`。

## 6. 数字公式（实现要写成门禁）

| 页面上的数 | 公式 |
|---|---|
| 「117 BPM」（列表和右侧栏同一个数） | round(60 ÷ 相邻拍间隔的中位数)。只显示整数 |
| 「每小节 4 拍」 | 相邻两个小节开头之间拍数的众数 |
| 「第 40 小节」 | 不晚于当前播放时间的小节开头个数；为 0 时不显示 |
| 放大区小节号 | 这个小节开头在全曲小节开头里的序号（从 1 起） |
| 当前段落名 | 包含当前播放时间的那一段的类型 |
| 「前面还有 N 首」 | 列表里排在它前面、状态为分析中或排队中的曲目数 |
| 放大区窗口 | 起点 = min(max(0, t − 4), max(0, 时长 − 8))，宽 8 秒 |
| 柱高 | 10 + 40 × 这一拍的响度（0–1，按整首 5%–95% 分位归一）像素 |
| 色带每段宽度 | (段终点 − 段起点) ÷ 时长，段与段之间留 2 像素 |
| 来源筛选计数 | 全部 = 曲目数；各来源 = 该来源曲目数 |
| 标签计数 | 满足来源筛选、并满足**其他各组**已选条件、并且标了这个标签的曲目数（标准分面计数） |
| 显示哪些标签 | 按清单从原始分数现算，规则只写在清单里，页面和接口共用一份实现 |

## 7. 清单和改动治理（按大厂通行做法定）

所有规则写在 `music-analysis.registry.json`，这里只说为什么这样定：

- **一份清单，配置即代码**：清单放仓库里，跟代码一起评审、一起留历史；有规范和校验脚本，校验不过就合不进去（`governance.change_gate`）。
- **编号稳定**：标签编号（例如 `scene.summer`）一经发布永不改、不复用；下线只把状态改成 `deprecated`。中文名可以改，编号不动，历史数据和以后的人工标注都对得上。
- **原始分数入库，标签读取时现算**：每首歌保存全部模型分数，以及当时的模型编号和清单版本。改名字、调阈值、隐藏标签，都按已存的分数立刻生效，不重跑模型。只有新增类别或换模型才整库重跑，本机每首 1–2 秒。
- **版本和改动记录**：每次改动 `registry_version` 加 1，`changelog` 记版本、日期、内容和需求卡。接口返回清单版本，页面和后台对不上时以接口为准。
- **谁能改**：
  - 用户（产品负责人）批准新增、改名、下线；
  - Claude 写需求卡、草稿和中文名，并审文案；
  - Codex 改清单、接模型、写门禁、跑整库重算；
  - 在 Studio 里，用户只能改某一首歌的标签（人工审核开放后），不能改清单。
- **没有模型能给出结果的类别不上线**：自定义标签（例如「适合开场」）等人工标注开放后，由人工逐首添加，或者以后接 CLAP 按文字描述匹配，届时另开卡。
- **本机实测**（2026-10-21，scratchpad 临时环境 `essentia-tensorflow==2.1b6.dev1389`，Python 3.12，没装进项目）：
  - 3 首每首推理 0.9–1.6 秒；
  - 进程峰值内存约 1.4 GB；
  - 5 个模型文件共约 27 MB，校验值已写进清单。
- **真实结果里要扛住的情况**：
  - Fever Pitch 的人声得分 0.55 对 0.45，标「拿不准」；
  - CRUSH VIBE 的细分风格最高才 0.12，只显示大类；场景一个也没过阈值；
  - 情绪、场景得分普遍偏低，最高 0.26。清单里的阈值是设计值，上线前按曲库校准，改阈值走上面的改动流程。

## 9. 页面要从后端拿到的数据

接口 `GET /api/review/music`：顶层加 `registry_version`；每首多两个对象 `beat` 和 `tags`，成败分开记。页面用的名字和顺序从接口带的清单展示部分读，不在前端另写。

```json
{"registry_version": 1,
 "taxonomy": "清单里 sections.kinds、tag_categories（编号、名字、状态、empty_text、uncertain_text）和 display 三部分原样带出",
 "tracks": [{
  "beat": {"status": "done | queued | analyzing | failed",
           "queue_position": 2,
           "bpm": 117, "meter": 4,
           "beats": [4.18, 4.714],
           "downbeats": [5.712, 7.802],
           "beat_energy": [0.52, 0.35],
           "sections": [{"start": 0, "end": 24.5, "kind": "quiet | build | peak"}],
           "failure": {"code": "audio_unreadable | worker_error | <其他>", "retryable": true}},
  "tags": {"status": "done | queued | analyzing | failed",
           "registry_version": 1,
           "genre": ["genre.electronic"], "style": "Tropical House",
           "mood": ["mood.deep", "mood.happy"], "scene": ["scene.summer"],
           "voice": ["voice.voice"],
           "voice_uncertain": false,
           "instrument": ["instrument.bass", "instrument.synthesizer", "instrument.keyboard"],
           "failure": {"code": "...", "retryable": true}}}]}
```

- 原始分数存在本机分析结果里，不随列表接口下发；以后审核页需要时另给接口。
- 曲目规范里 bpm、beats、sections 三个只能为空的字段：按讨论结论，**接页面之前必须处理**。处理方式二选一：删掉，或在接口投影时以分析结果为准。不允许接口同时出现 `bpm: null` 和 `beat.bpm: 117`。
- 失败代号对应界面上的三种说法：`worker_error` 对应可重试，`audio_unreadable` 对应换文件，其他代号对应「没认出是什么原因」并原样显示代号。不许把没认出的代号说成某个已知原因。节拍和标签都按这三种说法。
- 四小节、八小节的乐句这次不显示（讨论结论：乐句只是假设）。
- 数组长度：`beat_energy` 和 `beats` 一样长；`downbeats` 是 `beats` 的子集。
- 一首歌入库后，节拍和标签排进同一个分析队列，一次处理一首；库里已有的歌补分析也走这个队列。清单版本变了，按第 7 节决定是现算还是整库重跑。

### 10.1 给 R226 的两个接口（2026-10-21 定，改动先通知对方）

**后端读取函数**，在 `studio/music_analysis.py`：

```python
def load_beat_map(track_id: str, *, media_root: Path | None = None) -> dict: ...
class BeatMapUnavailable(Exception):
    code: str          # unknown_track | queued | analyzing | beat_failed | result_unreadable
    track_id: str
    failure_code: str | None   # code == "beat_failed" 时是分析记下的失败码，原样给出
```

- 返回（时间一律是这首歌自己的秒数，保留 3 位小数）：

  ```json
  {"track_id": "<file_sha256>", "title": "Turn Back Time", "duration_seconds": 189.924,
   "bpm": 117, "meter": 4,
   "beats": [4.18, 4.714],
   "downbeats": [5.712, 7.802],
   "beat_energy": [0.52, 0.35],
   "sections": [{"start": 0.0, "end": 24.497, "kind": "quiet"}],
   "registry_version": 1}
  ```

- 形状规则：
  - 第 k 小节从 `downbeats[k-1]` 开始；
  - `downbeats` 是 `beats` 的子集；
  - `beat_energy` 和 `beats` 一样长，取值 0–1；
  - `sections` 首尾相接，从 0 覆盖到 `duration_seconds`；
  - `bpm`、`meter` 的算法见第 6 节。
- 只读分析结果文件，不触发分析。拿不到完整结果就抛 `BeatMapUnavailable`。不许返回空数组或缺字段的半成品，读不懂结果文件时用 `result_unreadable`。
- 只管节拍，不带标签。

**前端模块**，`studio/static/beat-map.js`：

```js
export function mountBeatMap(container, options) // 返回 {update(partialOptions), setTime(t), destroy()}
options = {
  duration,          // 宿主时间轴总长（秒）。音乐库页 = 这首歌时长
  songs: [{          // 按宿主时间排好；音乐库页只有一首
    id, title,
    start, end,      // 这首在宿主时间轴上的起止（秒）
    offset,          // 宿主 start 那一刻对应歌里的第几秒，默认 0
    beatMap,         // load_beat_map 的返回，或接口里同形状的 beat 对象
    peaks            // 可选：整首歌的波形峰值（接口里的 peaks），按 offset 截取
  }],
  lane: true,        // 8 秒放大区；R226 传 false
  cuts: [],          // [{t, selected}]，宿主秒数；selected 的画 2px --fam-cut
  fadeOut: 0,        // 结尾淡出秒数；R226 传 1.6
  onSeek: null,      // (t) => void：点波形或色带任意位置，回传宿主秒数
  onSwapClick: null, // (index) => void：点第 index 个「换歌」标签（从 1 起，指第 index 首和第 index+1 首之间）；点标签不触发 onSeek
  selectedSwap: null // number | null：被选中的「换歌」标签画成实心；update({selectedSwap}) 可改
}
```

- 「换歌」标签是 `<button class="bm-swap">`。平时 1px `--ac` 边框、`--ac-bg` 底、圆角 9px、10.5px 字；选中时 `aria-pressed="true"`，样式选择器 `.bm-swap[aria-pressed="true"]`：底色 `--ac`，字色 `--bg`。

- 换歌竖线、歌名行和「换歌」标签只在 `songs.length > 1` 时画。
- 每首歌的小节按它自己的 `downbeats` 从 1 起编号。`lane: false` 时只画小节线，不显示小节号。
- `setTime(t)` 只移动播放线和放大区，不重画整条，播放时每帧调用不卡顿。
**重新分析接口**（R226 的「重新分析」按钮也调这个，不另做队列）：

- `POST /api/review/music/{trackId}/reanalyze`，`trackId` 是曲目的 `file_sha256`。
- 请求头：`Content-Type: application/json`；`X-Content-OS-CSRF` 带页面已有的安全令牌，和其他写操作一样；`Origin` 只许本机。
- 请求体：`{"part": "beat"}` 或 `{"part": "tags"}`。只重跑这一部分，另一部分的结果保留。
- 成功返回 `200`：`{"ok": true, "beat": {"status": "queued" | "analyzing", "queue_position": 2}}`。
  - 只带正在排队或正在分析的那部分，`tags` 同理；
  - 重复点击会合并成一次，返回同样的状态；
  - 完成后，`GET /api/review/music` 的 `beat.status` 变成 `done` 或 `failed`，`load_beat_map` 也不再抛 `queued` / `analyzing`。
- 失败：

  | 状态码 | 错误码 | 什么时候 |
  |---|---|---|
  | 400 | `music_part_invalid` | `part` 不是 `beat` 或 `tags` |
  | 404 | `music_track_not_found` | 没有这首歌 |
  | 403 | `csrf_invalid` / `origin_forbidden` | 令牌不对、不是本机页面 |

  - 返回体：`{"ok": false, "error": {"code": "...", "message": "中文说明"}}`。

- 音乐库页的调用是：`songs: [{id, title, start: 0, end: 时长, offset: 0, beatMap, peaks}]`、`lane: true`、`onSeek` 接播放器跳转。
