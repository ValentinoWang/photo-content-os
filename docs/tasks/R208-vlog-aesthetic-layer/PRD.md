## 4. 方案

一共五步，前两步解决「挑镜头」，第三、四步解决「卡点和节奏」，第五步是检查。

### 4.1 镜头切分与体检（本地确定性计算，不调模型）

- 用 PySceneDetect 把每段视频切成镜头；超过 8 秒的单个镜头按动感变化再切成 2–6 秒的候选段。
- 每个候选段在 20%、50%、80% 处各取一帧，量下面几项。阈值都是起始值，阶段 A 用兰大素材校准后写进合同：

| 项 | 量法 | 判为不能用 |
|---|---|---|
| 糊 | 拉普拉斯方差，跟本项目的中位数比 | 低于中位数的 40% |
| 过曝 / 欠曝 | 亮度直方图两端被截掉的比例 | 超过 25% 的像素 >250 或 <5 |
| 抖 | 帧间全局运动里的高频抖动 | 超过阈值，且不是有意的运镜 |
| 太短 | 时长 | 短于 0.8 秒 |
| 动感 | 光流强度 | 不淘汰，只作为排节奏的输入 |

- 结果写进 `shots.json`：每个镜头的来源、区间、各项数值、淘汰理由。**量不出来的标「未知」，不许当成合格。**

### 4.2 美感与去重

- **美感初筛**：用本地模型给每个镜头的关键帧打美感分（候选见第 3 节）。
- **去重**：同一场景里画面相似度高于 0.92 的镜头归成一组，只留总分最高的；连拍照片同样处理。
- **看图终选**：每个叙事位置只把分数前 3 的候选拼成一张拼图交给多模态模型（`llm_common` 已经支持传图），让它真看画面再选，并写一句入选理由。补上「分镜模型看不到画面」这个缺口。
- 总分 = 体检通过（不通过直接出局）+ 美感分 + 动感和节奏位置的匹配 + 叙事贴合。权重写进合同，审阅页上显示分项。

### 4.3 背景音乐：推荐与分析

**推荐**有三条路，可以同时存在：

| 路线 | 怎么做 | 开源件 | 好处 | 风险 |
|---|---|---|---|---|
| 甲：本地曲库检索（建议主线） | 大模型读这条 vlog 的分镜和镜头摘要，写出一段音乐描述（情绪、BPM 范围、能量走向、乐器）；用 CLAP 做「文字找音乐」，再按 BPM、时长、能量走向硬过滤，给出前 3 首和理由 | [LAION CLAP](https://github.com/LAION-AI/CLAP) 或 [msclap](https://huggingface.co/microsoft/msclap) 做文字和音频的匹配；beat_this 和 librosa 量节奏 | 曲子是真人作品，质量稳定；授权逐首可查 | 要先有一个曲库，本机现在只有 1 首 |
| 乙：本地生成 | 按 vlog 时长和要的 BPM、调性、风格，用 [ACE-Step 1.5](https://github.com/ace-step/ACE-Step-1.5) 现生成一首 | ACE-Step 1.5（MIT，支持 Mac MLX，可控时长 10 秒–10 分钟、BPM、调性；没写明能不能只出纯音乐） | 时长和节奏正好贴合，不用找曲 | Mac 上的速度和质量要实测；项目自己声明有风格相似导致侵权的风险；平台对 AI 音乐的态度不确定 |
| 丙：平台搜索词 | 大模型给出在剪映、抖音、小红书音乐库里能搜到的关键词和参考 BPM | 不需要 | 发布时用平台版权音乐最稳妥 | 系统拿不到曲子本身，只能用节奏相近的本地曲子先定切点 |

建议：**甲做主线，丙同时给出；乙放在阶段 B 末尾做一次实测**，好用再加进来。

**曲库主要来源（2026-10-19 用户定）**：用户粘贴汽水音乐、抖音、网易云音乐的分享链接导入，由 R210 实现（`docs/tasks/R210-music-link-import/`）。这些曲子标成「平台版权曲」：只用来定切点和本地预览，发布时在剪映或平台曲库里换用同一首。所以推荐结果要写明这首在剪映、抖音里能不能找到。

补充来源：只收能逐首记下授权的曲子，入库时把授权页存档。CC0 的可以直接用；CC-BY 的要在视频说明里署名，入库时记下署名文字；CC-BY-NC 的不收。候选来源有 Pixabay Music、Free Music Archive 里 CC0 / CC-BY 的曲子、Incompetech（CC-BY），以及你自己买的或录的。**不批量抓站**：第一批由 Codex 按风格挑 30–50 首、逐首下载并存授权页，或者你自己丢进曲库文件夹。

**分析**（不管曲子从哪来）：

- 输入：用户指定的一首，或推荐里用户选中的那一首。
- `beat_this` 测出拍子和重拍；librosa 按拍算响度、起音强度和亮度，得到能量曲线；按能量突变切出段落（安静 / 推进 / 高潮），再按 4 小节、8 小节标出乐句。
- 产出 `music-map.json`：BPM、每个拍子和重拍的时间、段落、乐句边界、能量曲线。

### 4.4 节奏编排（确定性规则加模型排叙事）

叙事顺序沿用现有分镜：开场钩子 → 发展 → 情绪收尾。下面这些时间规则由代码执行，不交给模型估：

| 规则 | 起始值 |
|---|---|
| 切点吸附 | 优先吸到重拍，其次普通拍；全部量化到输出帧 |
| 切点密度跟段落走 | 高潮段 1–2 拍切一次；推进段每小节一次；安静段 1–2 小节一次 |
| 镜长范围 | 最短 0.8 秒；最长 6 秒，有人声时除外；整片平均 3–4 秒 |
| 开场 | 前 3 秒放总分最高的 2–3 个镜头，每个 2 拍 |
| 长短交替 | 同一长度档的镜头不连着超过 3 个 |
| 动作高潮 | 镜头里动感峰值放在切点前 0.20–0.30 秒 |
| 不重复 | 同一场景不连着出现；同一段素材最多用一次 |
| 照片 | 放在短间隔，当节拍上的点缀 |
| 人声 | 不切在一句话中间（按转写的句子边界）；人声期间背景音乐压低 12 dB；每个切点音频淡入淡出 30 毫秒 |
| 结尾 | 在完整乐句末尾结束，音乐淡出 1.5–2 秒 |

产出照旧是现有合同的 EDL，加上音乐音轨。剪映草稿、ChatCut、Kdenlive 后端不用改接口。

### 4.5 审阅页与成片自检

- **审阅页**（生成草稿前）：一个静态 HTML 报告，不是剪辑界面。内容包括：
  - 每个位置入选的镜头：缩略图、分项得分、入选理由；
  - 落选的高分镜头；
  - 被淘汰的镜头和原因（糊、过曝、抖、重复）；
  - 音乐波形，上面标出拍子、段落和切点。
  用户看过点「生成草稿」，或者写意见后重排。审阅页按项目规矩，先由 Claude 出高保真设计稿给你看，再交给 Codex 实现。
- **成片自检**（生成之后）：在每个切点取前后两帧，量切点和最近拍子的偏差（不超过 1 帧），查有没有切在半句话上、背景音乐在人声时有没有压低。不合格的写进 `review_output_video` 的结果。
