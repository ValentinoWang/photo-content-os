## 交互（第 2 版，2026-10-26 按「交互不直接」重做）

在画面上直接点要改的地方，不再先读一长串文字再选问题。

- 左边是这一镜的大画面（360×640）。Opus 自己看出的问题用橙色「!」标在出问题的那一块上。
- 点画面上任意一块（悬停有虚线框，选中是实线框），右边出现「选中 · 这一块」：Opus 对这一块说了什么，和四个改法「做主角 / 缩小变灰 / 删掉 / 字改短」，Opus 建议的那个带「建议」角标。
- 选了改法，这一块在画面上出现青色编号，右边「要改的」多一条同号的具体要求，可以点 × 去掉。整镜的问题（太空、颜色乱、跟口播对不上）是「要改的」下面三个小按钮，再补一句可不填。
- 「重写这一镜」后，两版并排；第 2 版上用绿色编号标出每一处改在哪，右边逐条写「做到了」。退回第 1 版或用第 2 版。
- 「这镜好」放在这一镜标题右边，点了变「已存为样例」。
- 口播、规则检查、代码收在最下面，规则检查有要看的项时标橙色「1 项要看」。

## 设计编号

沿用 R276：`DV-DETAIL`、`DV-SCRUB`、`DV-CHECKS`、`DV-CODE`、`DV-HEAD`；`DV-SAY`（口播，收起）。
本稿新增：`RV-INSPECT`（选中这一块）、`RV-BRIEF`（要改的）、`RV-WHOLE`（整镜问题）、`RV-RATE`、`RV-BUSY`、`RV-COMPARE`、`RV-CHANGED`、`RV-LOG`、`RV-PROPOSAL`、`RV-SAMPLES`。

## 数字公式

- 修改要求字数 = 「要改的」各条文字 + 补的一句，字数之和，上限 200；超了按钮不可点，字数变红。
- 画面上的编号 = 这一块在「要改的」里的序号；整镜问题有序号但不落在画面上。
- 第几版：重写一次加一版；退回只改「用第几版」，不删版本。
- 问题记录「几次」= 这类改法真的发出去重写的次数（选了又去掉不算）；到 3 次起草规则，「再有 X 次会起草规则」里 X = 3 − 次数。

## 需要后端新加的（等 R276 总控决定接不接）

- 每镜画面上能点的块：渲染时在 0.8 处那一帧取镜头代码里各元素（带 id 或 `data-s` 的）的位置和大小，存成 `{id, 名称, x, y, w, h}`（1080×1920 坐标）。稿里只有第 02 镜画了热区，其他镜实现时按这份数据画。

- 每镜存多个版本：版本号、代码、渲染出的关键帧、发出去的修改意见（每条带来源：问题按钮 / 看图自查 / 自己写的）。退回只改「当前用哪一版」，不删版本。
- 看图自查：渲染后取 0.3、0.6、0.9 三帧和上面的块列表给 Opus，返回若干条 `{落在哪一块, 类别, 说明, 建议改法: 做主角|缩小变灰|删掉|字改短}`；失败时返回原因，不影响代码规则检查。
- 重写后核对：把发出去的每条要求和新画面再给 Opus 看一次，逐条返回「做到了 / 没做到 + 原因」。
- 样例库：镜头 id、作品、关键帧、代码、存的时间；写新镜时取最像的 2 个附给 Opus。
- 问题记录：按问题类别累计次数和出处；到 3 次生成规则草稿（规则版本号 → 新版本号、新增条文、依据）；「采用」后画面规则升一版，已经写好的镜不变。
