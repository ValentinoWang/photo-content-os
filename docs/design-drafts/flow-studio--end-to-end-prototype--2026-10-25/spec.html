2交互规则

怎么走

  • 步骤条每一步都能点，点了进那一步（现在是不能点的文字）。前一步没做完时，后一步页面照样能看，页头写清「要先做完第 n 步」并给去那一步的按钮，不灰掉整页。
  • 工作台每件事的按钮直接进那一步并选中那一项：挑镜头等你过目 → 第 2 步；对稿剪辑要你定 → 脚本第 3 步并滚到第一处要你定的；检查没通过 → 出片检查并选中没通过的那一版；整理台新素材 → 整理台并选中那一批；副本核对没通过 → 保存与归档。处理完那件事就从工作台消失，不用手动关。
  • 整理台定了去处才算处理完：放进已有作品 → 进那件作品「素材整理 › 补充素材」；新建作品 → 建好进第 1 步；先不决定 → 留在整理台，不进工作台。选择要真正生效（现在「仅归档」不生效，R225 S2）。
  • 分镜缺画面去素材库挑：素材库顶部出现「给《作品》第 n 镜挑画面」，详情里的按钮变成「放进第 n 镜」，点了直接回分镜并选中那一镜。
  • 缺条件的提醒块直接带去修的按钮：模型没登记 → 设置 › 模型；剪辑软件没装或没连上 → 设置 › 剪辑软件；上游中台没连上 → 设置 › 上游账号。修好回来，停在原来的位置。
  • 拍法在写稿页头选：口播 / 直出。换了拍法，第 3 步换成对应的页面；已经做的稿子和分镜保留。

网址

  • 沿用现有的 #view=piece&piece=<作品>&ptab=<vlog|script|tidy|archive>，加 &step=1-5；从工作台进来再加 &focus=<那一项>，页面滚到并选中它。
  • 浏览器后退回到进来前的页面和滚动位置。

每一页都守的规矩

  • 先画最差的真实首屏：每页第一个状态是你最先会遇到的样子（分析到一半、缺画面、检查没通过），不是演示用的「全好了」。
  • 要你处理的事单独一块，正文字号，带动作按钮；同一句话一屏只说一次；空值不占大字号；两块以上只有说明文字的空块合成一行状态。
  • AI 的建议都带理由，你拍板。AI 不删除、不发布、不替你定审美。删除只进系统废纸篓，勾选加二次确认；可以腾空间之前不出删除按钮。
  • 读不到不当成没有：读取失败写「读不到…」并给重试，不显示成空列表或 0。
  • 颜色：主色只用于当前位置和主按钮；黄色只用于要你处理；红色只用于失败和要剪掉的；绿色只用于检查通过。
  • 正在跑的事可以离开：分析、出草稿、渲染都在本机后台跑，离开页面不中断，回来接着显示进度；跑完进工作台。

6数字公式

数字怎么算在哪
分析进度这一档已看完的素材数 / 这一档要看的素材数；「深看」只算精选确认后的镜头vlog 1
对齐率口播稿里对上原片的句数 / 口播稿句数，保留一位小数对稿剪辑
可自动剪总时长自动剪的重说和静音区间先合并重叠部分再相加对稿剪辑
预计剪后时长原片时长 − 可自动剪总时长对稿剪辑
渲染进度已渲染帧数 / 这一镜总帧数（30 帧每秒 × 这一镜时长）逐镜动画
音画差实测音轨和画面的偏移秒数，允许值由出片检查给出；超过就不通过出片检查、人工精剪
切点对上拍子落在拍点前后 1 帧以内的切点数 / 切点总数人工精剪 · 成片复核
冷归档还差几天发布日期加约 1 个月，减今天；已发布满了就不显示保存与归档
可以腾出的空间这件作品在 Mac 上的原始素材总大小，减掉要留在 Mac 的精选和成片保存与归档
步骤条一格的宽度预算1440 宽：(1440 − 210 侧栏 − 48 边距) / 5 ≈ 236；说明行 11 号字，去掉圆圈和内边距后最多约 16 个字，超出用省略号所有作品页

7门禁（先写好，在现在的代码上会失败）

  • 没有占位入口：作品页不再出现只弹提示的按钮（现在「锁定范围」「版本与回滚」「失效传播」等点了只弹一句话），也不再出现写死宽度的「双轨时间线」。
  • 不写内联样式：Studio 的安全策略禁止 style=，现在时间线条宽和 Google 字体都被拦了。宽度、位置改用 CSS 类或在脚本里设置元素样式。
  • 步骤条可以点：每一步是按钮，点了路由到那一步。
  • 每页的最差首屏有对应的演示场景，按后端真实返回的形状造数据，截图门禁先走这个场景。
  • 读不到 ≠ 没有：每个列表接口返回失败时，页面显示「读不到…」和重试，不显示空状态文案。
  • 删除只进废纸篓且二次确认；保存与归档在条件没齐时页面上没有任何删除按钮。
  • 工作台和各页说同一件事时数字一致：工作台写「4 处要你定」，对稿剪辑页的复核数也是 4。
  • 文案比对：实现页的文字和设计编号用 check_design_contract.py check 比对本稿导出的合同，多出的文字要先进文案表。

10要你拍板

  • 新叫法：第 5 节那 9 个，可以逐个改。
  • 上游交接视图怎么并：现在从 MediaClaw 交过来的口播作品有一个单独的「剪这件作品」视图。本稿把它拆进「按脚本做视频」的第 3–5 步，交过来的作品和本机建的作品走同一条路。要不要这样并？
  • AI 写镜头代码放在哪：本稿画在 Studio 里，用本机的 Claude Code 写，代码确认后再同步给上游中台；另一种是只在上游中台写，Studio 只渲染和检查。前者离素材和渲染器近，能边写边预览；后者和现有上游流程一致。
  • 实现先做哪段。建议按「已有接口、只缺页面」的先做：写稿 → 对稿剪辑 → 出草稿 / 人工精剪（收回成片共用组件）→ 工作台汇总；「只有命令行」的（素材摘要、分镜配素材、素材整理、归档）先补接口再做页面。
